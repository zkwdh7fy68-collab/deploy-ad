04 / FEATURED CASE STUDY

From two virtual machines
to a connected domain.

Deploying Active Directory in Azure — a documented learning lab, not a production deployment.

EnvironmentMicrosoft Azure
Server / clientWindows Server / Windows Pro
Lab domainmydomain.com

The objective

Build on the prepared Azure network by making dc-1 a domain controller and joining client-1 to its domain. Create a dedicated administrator and organize users and computers into organizational units.

Before this lab: both VMs share a virtual network, dc-1 has a static private IP, and client-1 uses that address for DNS.

01 Install Active Directory Domain Services

On dc-1, use Server Manager’s Add Roles and Features wizard to install Active Directory Domain Services and its required features. Installing the role is separate from promoting the server.

View role selection screenshot ↗
02 Create the forest and domain

Promote dc-1 to a domain controller, choose a new forest, and use mydomain.com as the lab domain. Keep DNS Server and Global Catalog selected, set a recovery password, complete prerequisite checks, and restart after installation.

View forest creation screenshot ↗
03 Sign in with domain credentials

Reconnect using the lab’s domain account, mydomain.com\labuser. Specifying the domain identifies which directory the account belongs to.

04 Organize users with OUs

In Active Directory Users and Computers, create the _EMPLOYEES and _ADMINS organizational units. These are directory containers used to organize objects, not folders on disk.

View OU creation screenshot ↗
05 Create the administrator account

Create the lab user Jane Doe, with logon name jane_admin, inside _ADMINS. The account name and OU location alone do not grant administrator permissions.

View user creation screenshot ↗
06 Assign Domain Admins membership

Add jane_admin to the Domain Admins security group, verify the membership, and reconnect with that account for the remaining administrative tasks.

View group membership screenshot ↗
07 Join the Windows client

On client-1, open System Properties, change its membership to the mydomain.com domain, provide authorized domain credentials, and restart. The client’s DNS setting is essential for locating the domain controller.

View domain join screenshot ↗
08 Verify the computer account

Return to Active Directory Users and Computers on dc-1. Confirm that client-1 appears in the Computers container after joining the domain.

View client verification screenshot ↗
09 Give client computers their own OU

Create _CLIENTS, move client-1 into it, and confirm its placement. This separates client computer objects from the user and administrator OUs.

View client organization screenshot ↗
